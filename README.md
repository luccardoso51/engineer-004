## What the artifact actually does

`detect_anomalies()` classifies by measurable signal, not by hard-coded `event_id`, so it generalises past this fixture (see [ADR 0001](docs/adr/0001-timestamp-anomaly-classification-by-signal-not-id.md)). Against the checksummed sample it detects:

| Class | Events | Action |
|---|---|---|
| Duplicate `event_id` | `evt-0002` | `dedupe` |
| Clock skew | `evt-0005` | `flag_for_correction` |
| Timezone offset (not a future event) | `evt-0006` | `flag_for_correction` |
| Future timestamp | `evt-0016` | `flag_for_correction` |
| Missing `tenant_id` | `evt-0011` | `quarantine` |
| Unexpected PII | `evt-0007` | `quarantine` |
| Schema drift (legacy SDK shape) | `evt-0009` | `normalize` |
| Bot burst | `evt-0012`–`evt-0015` | `quarantine` |
| Malformed JSON | `evt-0020` | `dead_letter` |
| Privacy request (compliance, not a data-quality anomaly) | `evt-0017` | `route_compliance` |

The loader survives `evt-0020` — a corrupt line — by dead-lettering it with its line number, raw text, recovered `event_id`, and parser error, then continuing. That is the one failure path in this submission backed by code that actually runs rather than by design intent.

## Honest limits

Stated here so nothing has to be discovered:

- **Sizing, latency, and cost numbers are `[Estimated]` or `[Assumed]`.** There is no load test and no AWS bill behind them. Every number in the packet carries a source label; the ones worth interrogating are labelled as such.
- **The benchmark measures a subroutine, not the pipeline.** It times `detect_anomalies()` in-process over 24 events. It says nothing about end-to-end hot-path latency, and the written answer says so.
- **The AWS pipeline is designed, not built.** [`docs/failure-modes.md`](docs/failure-modes.md) marks each mitigation as *designed* or *observed* so the two are never conflated.
- **The MVP is single-region `us-east-1`,** with no automated cross-region failover. That is an accepted gap, with the reasoning in `docs/failure-modes.md` §1.3.
- **Detection thresholds are fixture-tuned heuristics,** not calibrated against production traffic. Retuning them is on the "what stays human" list.
- **The fixture is 25 lines.** Conclusions that a sample this small cannot support are named rather than drawn — see the refusals section of `docs/fixture-forensics.md`.
